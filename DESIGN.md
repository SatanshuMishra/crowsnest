# Design

## Look

Ledger: a Swiss, type-led look. Minimal, quiet, dense. Dark theme first with an equally finished light theme, chosen by the system setting unless the user picks one. The interface is chrome-free: the app draws its own title bar of plain text in place of the Windows one, then the two team tables set straight on the window. Hierarchy comes from type size, weight, position and hairline rules, never from boxes or colour. No cards, chips, pills, badges, coloured stripes, uppercase labels, decorative icons or gradients; the onboarding card is the one exception, where a soft wash, framed palette rows and a glyph tile introduce each page. Only floating layers cast a shadow: the player sheet, the onboarding card and its glyph tile, the preview popover and the toast.

## Colour

- The interface is monochrome: neutral greys with no blue cast. The one accent is ink. Primary buttons, selected segments and switches that are on invert text and background.
- Colour carries meaning only: the tier scale, the semantic tones (`--info`, `--warning`, `--danger`, `--success`), the focus ring (`--focus`), the division tag (`--division`) and the close button's hover red (`--window-close`), which follows the Windows convention.
- The division tag is a vivid sky blue that nothing else uses. Its hue sits in the gap the tier scale leaves, and it is more saturated and greener than the periwinkle of `--info` and `--focus`, so it never reads as a statistic tier or a notice. It meets 4.5:1 on every surface, highlight fill included, in both themes.
- The tier scale comes in three palettes, chosen by the Colour palette setting through `data-palette`. Muted, the default, keeps the eight community hues from WoWS Numbers (red, orange, yellow, light green, green, teal, pink, purple), softened to near-equal lightness so no single tier shouts. Vibrant keeps the same hues at full strength. Colour-blind friendly runs from orange through yellow to blues, purple and pink, leaving out the red and green pair that the common forms of colour blindness confuse. In every palette and theme each tier meets 4.5:1 as text on `--bg`, `--surface-raised` and `--surface-hover`; the tier name stays in text either way.
- Teams carry no colour. Allies sit on the left and enemies on the right, each headed by its name.
- Nothing on screen may suggest the user's location. The map name is not shown, and the region always reads as a game server ("NA server").

## Tokens

All colour, spacing, type and motion values live as CSS custom properties in `src/app.css`. Components use the tokens and never inline a new value; a new value goes into `app.css` first.

- Surfaces: `--bg`, `--surface`, `--surface-raised` (the player sheet), `--surface-hover`, `--me-fill` (your own row), `--border` (hairlines), `--border-strong` (header rules, control outlines).
- Text: `--text`, `--text-muted`, `--text-faint`. All three meet 4.5:1 on every surface in both themes.
- Accent: `--accent`, `--accent-strong`, `--accent-contrast` are ink, not a hue. `--ally`, `--enemy` and `--me` stay neutral.
- Division: `--division`, one colour shared by every division tag in both teams.
- Statistic tiers: `--tier-bad`, `--tier-below-average`, `--tier-average`, `--tier-good`, `--tier-very-good`, `--tier-great`, `--tier-unicum`, `--tier-super-unicum`, overridden per palette under `[data-theme][data-palette]`.
- Scoping: theme, palette, text size and density are attribute-scoped, so any element carrying `data-theme`, `data-palette`, `data-text-size` or `data-density` restyles its own subtree. Previews use this to render the real player table in a look the user has not chosen yet.
- Type: `--font-ui` and `--font-display` (Segoe UI Variable), `--font-mono` (Cascadia Mono). Sizes `--fs-xs` 12, `--fs-sm` 13, `--fs-md` 14, `--fs-lg` 16, `--fs-xl` 22, `--fs-2xl` 28 px (the onboarding title), all scaled by `--text-scale`, which the text-size setting changes through `data-text-size`. Weights `--weight-regular` (reading), `--weight-medium` (buttons), `--weight-strong` (titles and your own name only). `--tracking-display` tightens titles. Numbers use the `.num` class for tabular figures.
- Layout: `--row-height` (36 px comfortable, 30 px compact, never under 28 px), changed by `data-density`; `--cell-pad` for table cells; `--measure` for reading columns; `--pip-size` for the row marker; `--titlebar-height` (52 px) and `--window-control-width` (46 px) for the title bar.
- Window: `--window-close` and `--window-close-text` colour the close button on hover, the same in both themes.
- Layers: `--scrim` dims the window behind the onboarding card; `--onboarding-width` and `--onboarding-height` size the card, `--onboarding-hero` is its hero height on appearance pages and `--onboarding-tile` sizes a glyph tile; `--wash-teal`, `--wash-violet`, `--wash-amber` and `--wash-green` at `--wash-strength` tint each hero; `--popover-width` sizes the preview popover; `--toast-width` sizes the toast and `--toast-life` is how long it stays; `--nav-width` is the Settings section list, and `--settings-width` caps the section beside it, which otherwise fills the window.
- Space: `--space-1` to `--space-6`. Radius: `--radius-sm`, `--radius-md`, `--radius-lg`, `--radius-xl` (the onboarding card and its glyph tiles). Motion: `--duration-fast`, `--duration-base`, `--duration-exit`, `--ease-out` for entering, `--ease-in` for leaving.

## Patterns

- Title bar: one row at `--titlebar-height` holding the title (the match type in battle, otherwise Crowsnest) and the server on the left; the status, refresh and settings on the right; then the pin, set off by a hairline; then minimize, maximize and close at the window's edge in the Windows order. The window controls are `--window-control-width` wide, fill the bar's height and show glyphs only, each with an accessible name and a tooltip. Dragging any empty part of the bar moves the window and a double-click maximizes or restores it. The setup screen keeps the status and window controls without a title, and the start-up screen shows only the window controls. The player sheet opens below the bar.
- Team header: the team name at `--fs-xl`, its coverage ("11 of 12 with stats · mean") on the same line at the right, and the team figures on the line below in normal case.
- Table: column groups use booktabs-style spanner rules over "This ship" and "Account"; column heads are 12 px, muted and normal case; rows are separated by hairlines only. The table hangs into the window gutter, so names align with the team title while hover and fill tints keep breathing room.
- Statistic values: right-aligned tabular numbers. Coloured values tint win rate and personal rating only. Damage and frags stay plain because personal rating already scores them against expected values. The tier name is always the cell's title and accessible label, so colour is never the only cue.
- Row highlight: Edge is a small tier-coloured square hanging in the gutter left of the name; Fill tints the row at `--highlight-fill-alpha`; None shows neither.
- Division tag: players who queued together show their division's letter in brackets after the name, `[-REEE] CaptainMidway (A)`, in `--division`. Each team letters its own divisions from A in the order the game numbered them. The tag never truncates; a long name gives way first. Assistive technology hears "division A" instead of the brackets. When Crowsnest cannot read divisions for a battle it shows no tags rather than guessing.
- Ship cell: the tier numeral right-aligned in a fixed slot, the ship name, then the class abbreviation as faint text.
- Player sheet: an Account table and a This ship table, each with All, Solo, Div 2 and Div 3 columns over the same rows, so division play reads against solo play. The ship table shows skeleton cells while ship statistics load and is left out when the player has none for this ship.
- Your own row: `--me-fill` behind the row and your name at `--weight-strong`; the word "You" is there for assistive technology.
- States: waiting, loading, setup, replays-off and error screens are plain left-aligned text in a `--measure` column, with no icon and no card. The connection is stated once, in the title bar; the waiting screen says what it waits for instead: "Waiting for a battle" when connected, "Waiting for the replays folder" when not. Loading uses skeleton cells of the final row height, not spinners.
- Notices: one line above the tables, the icon in the tone colour, the text in body colour and a hairline below.
- Status: a 14 px radar glyph, then "Connected" or "Not connected", then what Crowsnest is doing ("Waiting for battle", "Loading stats", "In battle") or why it is not connected ("Setup needed", "Game not found", "Replays off", "Replays folder unavailable"). Colour states the connection: the glyph is `--success` when connected and `--warning`, with amber text, when not. Motion states the activity: the sweep turns slowly while waiting, quickly while statistics load and stops in battle. Connected means Crowsnest is watching the replays folder for battles, and the tooltip names that folder; Crowsnest does not watch the game process. The text always states both.
- Refresh: the icon spins while statistics load (at least 700 ms, so every press is acknowledged), then the button cools down for 10 seconds with the remaining seconds shown beside it. It uses `aria-disabled`, not `disabled`, so keyboard focus is never lost, and its label says when it will be available again.
- Controls are at least 28 px tall with a visible 2 px focus ring (`--focus`); a switch's hit area extends past its track. Icon-only buttons have an accessible name and a tooltip.
- Pin: a 32 px icon toggle for Always on top with `aria-pressed`. Off, the pin is outlined and tilted 45 degrees; on, it stands upright, filled, on the hover surface with a strong outline, so shape carries the state as well as tone. It keeps one width in both states so the buttons beside it never move.
- Settings: a section list on the left at `--nav-width` (Game, Statistics, Appearance, Window, Updates, About) under a search field, and the chosen section on the right. The list marks the current section with `aria-current`, a surface tint and strong weight. Search lists matching settings by name and section; choosing one opens its section, tints the setting and focuses its control. Sections group related settings under small headings separated by hairlines.
- Preview popover: pointing at or keyboard-focusing an Appearance option opens a popover with the real player table rendered on sample players in that option, the column driving the row highlight marked, and whether the option is in use. It opens below the setting, or above when below has less room, stays inside the window, and shrinks with a scroll when neither side fits. It stays open while the pointer is over it, and Escape, scrolling or resizing closes it.
- Onboarding card: one modal card over the window with a `--scrim` behind it, paged like a macOS welcome. Each page has a hero on top, washed with two soft radial tints that fade into the card, then a muted kicker, a large title and one muted line, left-aligned, and a footer with page dots on the left and two buttons on the right: Back, or on the first page Skip, which a new player who has changed nothing sees as Use the defaults; then Continue, which reads Done on the last page. The hero shows the sample team in the current look, the three palettes as swatches, or one glyph tile ringed in the wash colour; it never shows the app icon. Appearance pages add their settings below the line as segmented rows, each with the chosen option's caption, and every choice applies at once to the hero and the window behind. On a short window the appearance hero shrinks and the settings scroll.
- Who sees which pages: they come from `RELEASES` in `src/lib/intro.ts`. A new player sees a welcome, then the three appearance steps, Theme and size, Colour and Rows. A player updating sees a page for each feature of every release newer than the one they last saw, then the appearance steps only when one of those releases sets `appearanceForEveryone`. Release 1 sets it, so everyone sees the appearance steps once; later releases leave it off and show their features alone. Settings, Appearance opens the appearance steps alone as a tour.
- The card shows once per release, only on the monitor between battles. If a battle starts while it is open it closes unseen and returns at the next quiet moment, so it never covers a loading table. Focus starts on Continue, or on the first choice in a tour; Tab stays inside, Escape closes it, and focus returns to where it was. For a new player a toast confirms the look when they finish or change it, and otherwise says the defaults stay; an updating player or a tour gets a toast only when the look changed. Feature pages say What's new rather than a version, since one card can cover several releases. A change made before a battle interrupted the card still counts when it reopens. Earlier use is read from the window-state file when no settings were ever saved.
- Toast: one at a time at the bottom right, `--toast-width` wide, for the outcome of something the user started, such as saving appearance or refreshing statistics. A check or error icon, a title, one line of detail, an optional action and a dismiss button. A 2 px bar depletes over `--toast-life` and pauses while the pointer or focus is on the toast; errors stay until dismissed. Success is announced politely and errors as alerts, without moving focus.
- Errors appear inline next to what failed, never in a modal. A failed action the user started, such as Refresh, also raises an error toast with Try again.
- Motion is short and purposeful: a screen fades up 8 px when you switch views, a new battle's tables fade in, arriving values fade in over their skeletons, the player sheet slides in and out with its content kept while it closes, buttons press down 1 px and icon buttons scale slightly, the onboarding card rises and fades in over a fading scrim and leaves faster than it came, each of its pages slides in from the side it was reached from, and a toast slides up and its bar depletes. All motion stops when the system asks for reduced motion, except the toast bar, which keeps its timing so the toast still shows how long it will stay.
